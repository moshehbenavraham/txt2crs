# File Organization Guide

This guide maps the current txt2crs repository. It is a responsibility map:
feature code belongs at the boundary that owns the behavior.

## Repository Map

```text
txt2crs/
|-- backend/
|   |-- app/                       FastAPI application shell
|   |-- packages/txt2crs/         Reusable education engine
|   |-- tests/                     Shell and acceptance tests
|   `-- pyproject.toml             uv workspace and shell configuration
|-- frontend/
|   |-- src/routes/                TanStack file-based routes
|   |-- src/components/            Product and shadcn/Radix components
|   |-- src/client/                Generated OpenAPI client; do not edit
|   |-- src/lib/                   Shared schemas, types, and utilities
|   `-- tests/                     Playwright end-to-end tests
|-- docs/
|   |-- adr/                       Architecture Decision Records
|   |-- api/                       HTTP API documentation
|   |-- runbooks/                  Operational response procedures
|   `-- README_docs.md             Documentation index
|-- examples/                      Curated few-shot examples
|-- make-scenarios/                Legacy workflow evidence
|-- scripts/                       Repository validation and deployment tools
|-- .spec_system/                  Apex-spec state and phase evidence
|-- docker-compose.yml             Full-stack service topology
|-- VERSION                        Repository release version
`-- README.md                      Repository overview
```

## Backend Boundary

`backend/app/` owns HTTP, authentication, SQLModel application data, RFC 9457
errors, logging, deployment settings, and the read-only administrative MCP
server. Route handlers call the `txt2crs` package boundary; they must not copy
engine orchestration, research, persistence, validation, or rendering logic.

`backend/packages/txt2crs/src/txt2crs/` owns:

- domain models and invariants;
- application orchestration and public ports;
- AI runtime and research adapters;
- ingestion, jobs, persistence, and deterministic rendering;
- engine security, observability, and evaluations.

Package tests live in the package's `tests/` tree. Shell and product
acceptance tests live in `backend/tests/`.

## Frontend Boundary

React routes live in `frontend/src/routes/`. Shared validation schemas and
branded types live in `frontend/src/lib/`; they mirror backend validation.
Reusable presentation components live in `frontend/src/components/`.

Never edit these generated files manually:

| Path | Source | Refresh command |
|------|--------|-----------------|
| `frontend/src/client/` | FastAPI OpenAPI schema | `cd frontend && npm run generate-client` |
| `frontend/src/routeTree.gen.ts` | TanStack Router | Generated by route tooling |

Alembic migrations are reviewed source files after generation, not disposable
generated output. Every application database schema change requires a
migration under `backend/app/alembic/versions/`.

## Documentation Boundary

The repository root alone uses the filename `README.md`. Directory indexes use
`README_<scope>.md`, including:

- `docs/README_docs.md`
- `docs/adr/README_adr.md`
- `docs/api/README_api.md`
- `backend/README_backend.md`
- `frontend/README_frontend.md`
- `backend/packages/txt2crs/README_txt2crs.md`

Architecture decisions are immutable records in `docs/adr/`. Create a new ADR
to supersede an accepted decision. Product requirements, phase/session state,
and active delivery work belong in `.spec_system/`; completed user-visible and
engineering work is recorded in `docs/CHANGELOG.md`.

## Naming Conventions

| Artifact | Convention | Example |
|----------|------------|---------|
| Python module or function | `snake_case` | `course_service.py` |
| Python class | `PascalCase` | `CourseRequest` |
| Python test | `test_*.py` | `test_courses.py` |
| React component or TS type | `PascalCase` | `CourseBuilder.tsx` |
| TypeScript function or hook | `camelCase` | `useCourseJob` |
| Unit test | `*.test.ts` or `test_*.py` | `securityHeaders.test.ts` |
| Playwright test | `*.spec.ts` | `course-flow.spec.ts` |
| Log event | `{domain}.{action}_{state}` | `course.generation_started` |

Use descriptive names and place tests before implementation. Run
`./scripts/validate-changes.sh` before committing cross-stack changes.
